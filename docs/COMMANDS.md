# Accepted commands

Generated by `uv run python scripts/generate_commands.py` from the live patterns, token sets, and maps in `voicebar/parser.py`; examples come from `tests/test_parser_contract.py`. Do not edit this file by hand.

Run `uv run python scripts/generate_commands.py --check` to detect drift.

Patterns below are Python regular expressions over normalized command tokens. Parentheses describe groups, `|` separates alternatives, `?` makes the preceding part optional, and `.+` is a nonempty target or payload. Every command must consume its complete clause; unknown or ambiguous targets make the whole plan `null`.

## open_app

| Accepted grammar | Result / detail |

| `^(?:open up\|open\|launch\|start\|run\|pull up\|bring up\|show me\|show) (.+)$` | app / configured site / domain |

## type_text

| Accepted grammar | Result / detail |

| `type <text>` | raw text; optional submit suffix below |
| `write <text>` | raw text; optional submit suffix below |
| `dictate <text>` | raw text; optional submit suffix below |

Contract examples: `open chrome type hello`, `type hello world`, `Type Hello world.`.

Typing and searching consume the rest of the utterance, including command-looking words. Typing strips one of these nonempty-payload suffixes and sets `submit=true`:

- `and then press enter`
- `and then press return`
- `and then hit enter`
- `and then hit return`
- `and press enter`
- `and press return`
- `and hit enter`
- `and hit return`
- `then press enter`
- `then press return`
- `then hit enter`
- `then hit return`
- `press enter`
- `press return`
- `hit enter`
- `hit return`
- `and send it`
- `and send`
- `and submit`

Payloads preserve raw case and internal punctuation. They trim spaces, periods, commas, semicolons and colons at the end, and spaces, commas, semicolons and colons at the start; `?` and `!` survive.

## Shared target resolution

Leading articles: `a`, `an`, `my`, `the`.

Target noise removed before a second resolution attempt: leading `new`; trailing `app`, `application`, `browser`, `document`, `program`, `window`.

Resolution tries configured aliases, exact app names, configured sites, spoken/literal domains, whole-word app subsets, then full-string app similarity. Alias and exact-name matching ignores spaces, case, and token-edge punctuation using `^[^\w']+|[^\w']+$`. Duplicate normalized app names are ambiguous and reject the utterance before command splits can reinterpret the target. Domain grammar: `^[a-z0-9-]+(\.[a-z0-9-]+)+$`; spoken `dot` is accepted. Fuzzy minimum: 85; required lead over runner-up: 5.

## Politeness and chaining

Repeated removable leading phrases: `hey`, `ok`, `okay`, `please`, `um`, `uh`, `ah`, `now`, `just`, `can you`, `could you`, `would you`, `will you`, `go ahead and`.

Repeated removable trailing phrases: `please`, `for me`, `now`, `real quick`, `thanks`, `thank you`.

Whole clauses are attempted before splits. Joins: `and then`, `and`, `then`, punctuation boundaries, or any word boundary. All clauses must parse. A following bare target can inherit `open`, `switch`, or `close`. Non-payload command limit: 40 tokens.

`app_action` is reserved for Stage 7 and has no Stage 1 grammar.
