# Record your command fixtures

Run `voicebar record-set` in an interactive native Windows terminal. Recording uses the current system default microphone and displays its name before capture. It saves local WAV files and expected plans; it never runs a command or opens an application.

For each of 40 prompts:

1. Read the displayed command. Press Enter when ready to start the microphone, or `s` to skip, or `q` to save and quit.
2. Wait for **Ready — say the command** before speaking. The microphone must deliver its first valid audio frame before that cue appears. Say the command naturally, then press Enter to stop. Capture closes automatically after 20 seconds measured from the first audio frame, including when no Enter arrives. Time spent opening the Windows audio stream does not consume that cap.
3. Review the signal measurements. Enter keeps a usable take; `r` retries; `s` skips; `q` saves and quits. Empty, extremely quiet, short, clipped, or lost-audio takes require a retry or skip.

Only the current prompt's recording opens the microphone. Waiting, reviewing, and quitting leave its stream closed. Ctrl+C closes capture and preserves the session. There is no playback, transcription, benchmark, or automatic execution during recording.

After Enter, `Starting microphone; wait for the Ready cue before speaking` means the device is still opening. Do not speak at that message. The readiness cue is flushed to the console only after a valid nonempty PCM callback buffer has been stored. The Enter-to-stop reader starts after the readiness cue; failed startup cannot leave a reader waiting on Enter. Startup normally has a five-second deadline, configurable through the Python `startup_timeout` argument up to 30 seconds. A failed/timed-out startup closes capture and records a retryable error without selecting a WAV.

If a native audio driver fails to return or close within the cleanup deadline, recording aborts the session and asks you to exit the process before retrying. No additional take starts in that process. Python cannot safely interrupt a native driver call; process exit lets Windows release its handles. This is a failure boundary, not a claim that an unresponsive driver has already closed.

Every session has a unique directory under `fixtures/mine`, for example `20261009T190000Z-quiet-12ab34cd`. A resume directory uses the same manifest and continues with pending prompts. Recorded and skipped prompts are preserved. Use another session label, such as `fan`, for another environment; this does not change expected commands. A complete session contains 40 accepted takes. Skips remain visible and do not count as completion.

The prompt list is deterministic and drawn from the first 117 commands in the locked parser contract, covering apps, chains, windows, browser controls, searches, typing, keys, scrolling, volume, media, and modes. App targets are rewritten to unique installed app names. The parser validates every saved expected plan before any capture begins. This deliberately includes commands that would close or type if executed; recording them causes no action.

Each manifest records the contract SHA-256, source index and utterance, substituted installed targets, catalog and prompt-set fingerprints, expected text and plan, and capture device. New sessions also record the first-frame readiness protocol and startup deadline. Each take records a WAV checksum, timestamp, duration, RMS, peak, clipped fraction, capture flags, cap status, and keep/retry/skip/quit decision. New native takes include their first-frame startup delay and the cap's starting event. WAVs are PCM, 16 kHz, mono, 16-bit. Retried takes are retained for provenance; only the explicitly kept take is selected. Both WAV and JSON saves replace temporary files atomically. A crash between WAV and manifest saves can leave an unselected orphan WAV, which cannot silently become a benchmark fixture.

Signal checks reject recordings under 0.25 seconds, RMS below 0.001 of full scale, at least 1% clipped samples, incomplete samples, audio past the cap, or any capture status reporting invalid/lost audio. These checks do not establish that the right words were spoken. Resume refuses changed contract/config/prompt provenance, altered WAV checksums, unexpected audio format, or paths outside the session.

After completing the recordings, stop and ask the user before step 6. Recognition benchmarks and backend selection need that separate go-ahead. Mishearing aliases are proposals for approval, never automatic changes.

Implementation API: `record_set(root, loaded, *, session_label='quiet', session_dir=None, input_fn=input, output_fn=<flushed console output>, recorder=None, stop_fn=None, max_seconds=20.0, startup_timeout=5.0)` returns `RecordingSession(path, manifest, completed)`. `build_prompts(root, loaded)` returns the 40 validated prompt dictionaries and provenance. An injected recorder implements `capture(stop, max_seconds, *, ready, startup_timeout)`: it stores the first valid frame, sets the `ready` event, then continues capturing until stop or its cap. A recorder that returns before confirming readiness is rejected. Unit tests inject generated PCM, readiness events, controls, and a fake recorder; they never open the microphone.

The real adapter uses the checked sounddevice 0.5.3 APIs [RawInputStream](https://python-sounddevice.readthedocs.io/en/0.5.3/api/raw-streams.html) and [default input/device checks](https://python-sounddevice.readthedocs.io/en/0.5.3/api/checking-hardware.html). It fixes the selected default device for each take, requests int16/one channel/16 kHz, copies callback buffers, and closes the context on stop, cap, or exception.

Read-only inspection of the installed sounddevice 0.5.3 source confirms that entering a stream context calls `start()` and exiting calls `stop()` then `close()`. Successful context entry alone does not establish that input callbacks have delivered samples. The readiness repair uses the first valid callback instead, with monotonic deadlines and `threading.Event` waits; no fixed sleep substitutes for readiness. Existing recordings and expected plans are preserved. Their signal measurements alone cannot establish whether an opening word was clipped, so earlier recordings are not silently repaired or rescored as if a new recording had been made.
