# Push-to-talk

The configurable candidate shortcut is `ctrl+alt+f8`. After models load, hold the entire chord and wait for `Ready — speak` before speaking. That cue is printed and flushed only after the first microphone frame arrives. This confirms Windows has delivered audio; it cannot establish whether the microphone's hardware processing has settled, so real recording checks are still required. Keep holding while speaking and release any chord key to finish. The microphone is closed while waiting and during recognition after release. Ctrl+C unregisters the hotkey, closes capture, and stops the service.

The CLI allows candidate-backend PTT diagnostics only with an explicit `--backend` and `--dry-run` while no engine has passed the recording accuracy gate. The API supports an executor for a later authorized human gate, but a null configured engine never enables live CLI execution. Failed accuracy gates must be resolved before that live gate or later stages.

Registration uses Windows `RegisterHotKey` with `MOD_NOREPEAT`, not a keyboard hook. A collision fails before models load or capture opens; choose another configured shortcut. Win combinations and F12 are rejected, and Alt+Space is rejected because it conflicts with the Windows window menu and PowerToys Run. PowerToys Command Palette, Keyboard Manager remaps, and Claude's user-configured quick-entry shortcut also need review. Registration is the runtime collision check. `probe_hotkey(text)` registers and immediately unregisters without loading models or opening the microphone; development tests do not run it.

One recognizer loads while the microphone is closed and is reused. PortAudio callbacks only copy fixed-format PCM into a bounded queue. A separate worker feeds 16 kHz mono samples to the streaming backend and emits provisional text; provisional text never executes. On release, capture closes before recognition drains its remaining audio and flushes finals. Finals are deduplicated by line ID, combined, parsed all-or-nothing, and validated against the closed schema. Unknown text prints its transcript with a null plan. Silence suppresses hallucinated command text. Dry-run prints the plan without constructing an executor context.

The default cap is 20 seconds, audio backlog is at most about two seconds of 512-sample frames, and recognition has a 30-second completion deadline. Lost audio, malformed frames, cap expiry, queue overflow, model errors, or invalid plans stop without executing that utterance. Any secure/locked desktop closes capture and discards the command; the desktop is checked again before execution. A native inference call cannot be forcibly interrupted safely in this one-process design. If it exceeds the deadline, capture and the hotkey close immediately, no actions run, and the model is freed by its worker when that call returns. The service does not open another capture stream afterward.

Native microphone open/start/close calls run on a separate daemon worker, so the controller can continue checking release, lock, and cancellation while a driver call waits. The first stored frame has a five-second startup deadline. Release clears acceptance before requesting closure; late callback buffers cannot become another command. Closure normally has a five-second deadline, during which lock/cancellation still discard the utterance. If closure cannot be confirmed, the log retains `capture_closed: null` or `false` and `process_exit_required: true`; no execution occurs and another capture is refused in that process, even if the blocked driver later returns. Python cannot safely kill that native call. Exiting the process is the recovery boundary; the code does not falsely report that the Windows microphone indicator has already gone away.

Capture results and failures are printed as JSON and appended locally under `logs/ptt-*.jsonl`, including heard text, plan, backend/device, provisional/final events, capture metadata, and execution results. Failures retain the error type, capture-closed state, and whether execution was attempted. Recognition and validation failures record `executed: false`; an executor that raises after entry records an unknown mutation outcome. Capture adapters can expose `is_open` for reliable closure diagnostics even when cleanup follows an exception. Release-to-final includes queued inference after release and microphone closure. It is measured from the controller's observed key release; 5 ms polling adds observation granularity. Last-speech-to-final is left null because PTT release is not an independently labeled speech endpoint. Action-start timing is supplied by the executor trace; injected executors without that trace report null instead of inventing a measurement.

API: `listen_ptt(root, loaded, *, backend_name='moonshine', device='cpu', hotkey='ctrl+alt+f8', dry_run=False, stop_event=None, max_utterances=None, hotkeys=None, microphone=None, backend_factory=None, executor=None, state_reader=None, output_fn=print, max_seconds=20.0, backlog_seconds=2.0, recognition_timeout=30.0, startup_timeout=5.0, cleanup_timeout=5.0)` returns `PttReport(utterances, last_result, log_path)`.

An injected executor receives a schema-validated plan. For the human gate, pass a callback that invokes the existing executor with an ownership-restricted Context, and a `state_reader` returning that context's current `last_app`. Return `PttExecution(results, action_started_at)` to include a monotonic mutation-start timestamp, or a result list with timing left unknown. The default path reads the persisted last app, ignores stale or ambiguous names, and lets the executor update state. The controller never updates last-app state from a partial or a failed plan.

Tests inject all hotkeys, microphone streams, recognizers, and executors. They cover collisions, high-bit key state, secure desktops, release cleanup, resource failures, bounded buffers/deadlines, Ctrl+C, dry-run, malformed/unknown plans, and state continuity. No test registers a real hotkey, opens a microphone, or changes a window.

Checked APIs: [RegisterHotKey](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey), [PeekMessageW](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-peekmessagew), [GetAsyncKeyState](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getasynckeystate), [OpenInputDesktop](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-openinputdesktop), [GetUserObjectInformationW](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getuserobjectinformationw), and [sounddevice 0.5.3 streams](https://python-sounddevice.readthedocs.io/en/0.5.3/api/streams.html). Installed sounddevice source confirms `close()` aborts active input and discards pending buffers.
