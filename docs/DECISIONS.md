## Stage 2: native executor

Recorded 2026-10-09. Python 3.12.13 standard-library ctypes supplies the native
boundary; no additional runtime dependency. Read installed Windows SDK
10.0.26100.0 headers before declaring structures, constants, GUIDs and COM vtables.
`WINDOWPLACEMENT` is 44 bytes (the documented extra rcDevice is Mac-only in the
header); full-union `INPUT` is 40 bytes on this x64 interpreter. All native
functions declare argument and return types. Importing modules does not load DLLs.

### Identity, launch and foreground

Cache read-only AppsFolder metadata alongside StartApps: AppID, full link target,
arguments. Match a visible, titled, non-tool, uncloaked top-level window by explicit
window/process AUMID first. For ApplicationFrameHost, inspect child process AUMIDs
and attribute only that child's application to the top-level frame. If explicit
identity is absent, use an exact normalized full executable path whose shell
registrations identify one app and have no conflicting arguments. Shared hosts and
ambiguous names refuse. Chrome/Electron renderer processes do not become close
targets. Every mutation rechecks HWND/PID, ownership and integrity.
[AppID limitations](https://learn.microsoft.com/en-us/windows/win32/shell/appids),
[window property store](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-shgetpropertystoreforwindow),
[process AUMID](https://learn.microsoft.com/en-us/windows/win32/api/appmodel/nf-appmodel-getapplicationusermodelid).

Launch the installed AppID using Windows Explorer's AppsFolder activation with a
fixed argv and shell=False. Microsoft documents this route for packaged Calculator;
the shell resolves classic registrations too. An initial in-process PIDL /
ShellExecuteEx implementation launched successfully but produced handled
CO_E_NOTINITIALIZED diagnostics during COM teardown. A read-only property-store
probe had no diagnostic. Delegating activation to Explorer avoids hosting package
shell extensions in the executor; diagnostics remain enabled. Completion still
requires observing the actual matching window, never Explorer's process exit.
[Microsoft launch example](https://github.com/MicrosoftDocs/windows-dev-docs/blob/docs/hub/apps/distribute-through-store/how-to-transition-users-from-your-web-unpackaged-app-to-store-packaged-app.md#how-to-launch-the-store-application-from-your-web-unpackaged-app).

Reuse existing windows except configured browsers, File Explorer and Notepad.
For an already authorized/owned window, their documented new-window keyboard
commands create another window; otherwise activate its AppID. Adopt only one
proven new HWND/PID. The startup predicate has a configurable 30-second deadline.
Tests refuse even AppsFolder activation when it could reuse an unowned window.
Fusion's launcher hands off to a different executable: its current main executable
was read from the running process and verified with FileDescription=Autodesk Fusion,
CompanyName=Autodesk, Inc., ProductName=Fusion360 before adding the local override.
No action was performed on the user's existing Fusion or Claude windows. A future
Fusion update may require refreshing that explicit verified path.

Foreground method: restore minimized windows, try SetForegroundWindow directly,
then temporarily AttachThreadInput between caller/foreground/target threads,
BringWindowToTop and SetForegroundWindow; detach every successful attachment in
finally. Query GetForegroundWindow to confirm. Windows has no universal foreground
guarantee: menus, another desktop, foreground locks and competing user input can
deny it. There is no synthetic Alt fallback, timeout setting change or elevation.
[Foreground restrictions](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setforegroundwindow),
[AttachThreadInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-attachthreadinput).

### Windows and input

Compare target/current integrity RIDs from TokenIntegrityLevel before messages or
input; a higher or inaccessible target refuses with a plain reason. WM_CLOSE is
posted to each identity-proven top-level app window, never a process kill. Pending
save prompts remain for the user and unconfirmed close stops the plan.
[Integrity model](https://learn.microsoft.com/en-us/windows/win32/secauthz/mandatory-integrity-control),
[token query](https://learn.microsoft.com/en-us/windows/win32/api/securitybaseapi/nf-securitybaseapi-gettokeninformation).

Geometry queries/mutations run under scoped per-monitor-v2 thread awareness.
Monitors sort by left/top/device. Next/prev cycle; left/right choose leftmost /
rightmost; primary uses the primary flag. Restore before moving, translate within
work areas with destination/source scale, clamp, verify monitor/rect, and restore
maximized/minimized state. Snap positions the normal window in a work-area half.
Only deadline expiry is handled as a timeout; native query errors propagate.
[DPI scope](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setthreaddpiawarenesscontext),
[monitor scale](https://learn.microsoft.com/en-us/windows/win32/api/shellscalingapi/nf-shellscalingapi-getscalefactorformonitor),
[placement coordinate caveat](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-windowplacement).

Actual Notepad tests exposed two timing/representation issues. Its titled window
can appear before its editor owns focus; wait for the actual editor, using UI
Automation focus queries on a separate windowless MTA thread when WinUI presents
a proxy HWND. Keep COM pointers on that thread. Short text uses EM_REPLACESEL with
undo and confirms the predicted selection replacement. RichEdit selection indices
count CR once while WM_GETTEXT expands CRLF; convert before UTF-16 indexing.
Generic editors receive Unicode packets per code point with surrogate pairs kept
together, but consumption cannot be confirmed. Whole-utterance packet batches
corrupted text on this Notepad version and are not used.
[UI Automation threading](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-threading),
[focused element](https://learn.microsoft.com/en-us/windows/win32/api/uiautomationclient/nf-uiautomationclient-iuiautomation-getfocusedelement),
[EM_REPLACESEL](https://learn.microsoft.com/en-us/windows/win32/controls/em-replacesel),
[RichEdit text conventions](https://learn.microsoft.com/en-us/windows/win32/api/richedit/ns-richedit-gettextex).

Long text snapshots every clipboard format independently, refuses unsupported or
uncopyable formats before overwriting, and publishes CF_UNICODETEXT using a hidden
owner HWND. Direct WM_PASTE on this modern Notepad's internal control was
intermittently ignored. Route Ctrl+V through the app and retain temporary clipboard
data until exact text readback confirms consumption, then restore every saved
format. Restore only while the clipboard sequence still belongs to this operation;
a concurrent user copy wins. Custom editors without a readable Edit/RichEdit
refuse long text. No fixed post-paste sleep or immediate speculative restore.
[Clipboard duplication](https://learn.microsoft.com/en-us/windows/win32/api/ole2/nf-ole2-oleduplicatedata),
[clipboard ownership](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setclipboarddata).

Shortcuts, wheel, volume and media use SendInput with exact event-count checks and
release only injected keys after partial failure. Held physical modifiers and
foreground changes refuse. Wheel events additionally require the pointer over the
guarded foreground window because Windows can scroll inactive hovered windows.
Mute/unmute query Core Audio state first; volume directions query the result.
Media player consumption remains unobservable. Physical function keys F1-F24 are
supported; the parser's wider numeric vocabulary gets an execution error.
[SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput).

### Browser, scope and timing

Resolve the current protocol-default executable using AssocQueryStringW. Chrome /
Edge launch validated URLs via fixed --new-window argv; observe a new matching
window before adopting it. Other defaults use OS association dispatch only outside
tests and explicitly report unobserved browser state. Search queries use UTF-8
quote_plus. Tab/nav require a configured browser identity and preserve the verified
target through input. Site-close checks word-bounded title hints or host boundaries;
it does nothing on mismatch. Close confirmation requires title/window change;
identical titles can leave completion unconfirmed. Navigation/page loads have no
content-level verification through these APIs.
[Association query](https://learn.microsoft.com/en-us/windows/win32/api/shlwapi/nf-shlwapi-assocquerystringw),
[Chromium new-window switch](https://github.com/chromium/chromium/blob/main/chrome/common/chrome_switches.h).

The dispatcher validates the whole plan and refuses later-stage mode/app_action
tails before any action; failures skip remaining actions. Results distinguish
completion milliseconds from action-start latency. Benchmarks use one-action calls
with an already initialized context; CLI initialization/metadata refresh and app
launch wait are separate costs. Queued timings include earlier plan actions.

Integration/gate sessions restrict every mutation to their recorded HWND/PID set.
Record ownership durably on adoption so cleanup does not infer ownership by name.
Before test typing, prove the new Notepad editor blank; restored text is untouched.
Clear only text the tests typed. Tests query placement, foreground, monitor, title,
exact Unicode/multiline contents and clipboard fingerprints. A physical second
monitor is absent; that integration case skips explicitly. Unit tests cover monitor
ordering, negative origins and differing scaling, but cannot prove hardware behavior.

## Stage 3 preparation: awaiting the speaker's fixtures

Checked the current documentation, pinned wrapper source, installed signatures,
and Windows wheels on 2026-10-09 before implementation. The two working CPU
candidates are Moonshine Small Streaming English (`moonshine-voice` 0.1.5) and
Parakeet TDT 0.6B v3 int8 (`onnx-asr` 0.12.0, ONNX Runtime 1.31.0), with Silero VAD.
Both installed and transcribed a locally synthesized “open chrome” into the
expected plan. This is a smoke test, not evidence for selecting either engine.
There was no installation/runtime failure requiring the faster-whisper fallback.

Moonshine emits native partial/final line events. The adapter deduplicates final
lines by ID and supplies the installed app names, aliases, and site names through
`set_keyterms`, excluding comma-containing phrases as required by the API. Boost
is the documented 2.0 default. Shipped Moonshine 0.1.5 supports CPU only; installing
Python ORT with CUDA does not make its bundled runtime a GPU engine.
[Pinned Python wrapper](https://github.com/moonshine-ai/moonshine/blob/v0.1.5/language-bindings/python/src/moonshine_voice/transcriber.py),
[Keyterms](https://moonshine-voice.readthedocs.io/en/latest/models/domain-customization/),
[Execution providers](https://github.com/moonshine-ai/moonshine/blob/v0.1.5/docs/execution-providers.md).

Parakeet has no documented hotword API. Its provisional partials use prefix
redecoding on a single recognition worker at a bounded audio cadence, with no
queue of obsolete partial jobs. Silero runs exact 512-sample frames with 64
context samples and reset recurrent state for each utterance. Its 300 ms silence
endpoint is included in future speech-end measurements. The recorder runs
capture separately; no PortAudio callback performs inference. The current CPU
candidate fixes ORT inference threads at four and VAD threads at one to bound
contention. These are implementation choices, not threshold changes to pass a gate.
[onnx-asr usage](https://istupakov.github.io/onnx-asr/usage/),
[Pinned loader](https://github.com/istupakov/onnx-asr/blob/v0.12.0/src/onnx_asr/loader.py),
[Silero inputs/state](https://github.com/istupakov/onnx-asr/blob/v0.12.0/src/onnx_asr/models/silero.py).

`scripts/setup.py` is the downloader. It stores the Moonshine helper's actual
nested model root, resolves the Parakeet/Silero Hugging Face revisions, and records
file sizes and SHA-256 values in `models/manifest.json`. Repeating completed setup
checks hashes and downloads nothing. Runtime requires the manifest, existing
directories, and every listed asset, sets the HF offline/telemetry switches before
imports, and never calls a downloader. This matters because onnx-asr treats an
existing directory as offline, while a missing directory can trigger a download.
The Parakeet checkpoint is CC BY 4.0; its source and revision are retained in the
manifest. All current model assets live under the Git-ignored `models/` directory.
[Parakeet checkpoint](https://huggingface.co/istupakov/parakeet-tdt-0.6b-v3-onnx),
[Silero checkpoint](https://huggingface.co/istupakov/silero-vad-onnx),
[HF offline switches](https://huggingface.co/docs/huggingface_hub/package_reference/environment_variables).

Offline evidence uses a fresh subprocess, before model imports, with a monitored
GO handshake, blocked Python socket/DNS calls, local file hash validation, and
native Windows IPv4/IPv6 TCP/UDP tables sampled throughout load and inference.
It rejects clients, listeners, unexpected UDP, monitoring failures, and runtime
network attempts. Synthetic canaries exercise the audit guard before system calls.
The report includes sampling gaps: native code can bypass Python audit hooks and
polling can miss a connection that exists wholly between samples. Network adapters
and firewall settings remain untouched. This proves the observed offline path,
not an OS security boundary. A scoped Windows job owns only the proof worker and
its descendants so failed proof cleanup cannot leave inference running.
[IP Helper tables](https://learn.microsoft.com/en-us/windows/win32/api/iphlpapi/nf-iphlpapi-getextendedtcptable),
[Python audit events](https://docs.python.org/3.12/library/audit_events.html),
[Windows jobs](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects).

The entire unchanged parser contract yields 144 evaluations, including four
previous-app cases. Native PowerShell `System.Speech` created 288 PCM16/16 kHz/mono
